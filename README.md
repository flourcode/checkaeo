# CheckAEO

**CheckAEO** is the tool. The **AEO Card** is the result it produces.

**Can AI understand your website?**  
CheckAEO checks how ready a site is for AI answer engines (ChatGPT, Claude, Gemini, Perplexity) and produces a shareable **AEO Card**: an overall score, four category grades (Access · Clarity · Answers · Trust), a "What AI sees" summary, and the three things to fix first.

It is a diagnostic, not a guarantee. The site never promises rankings or citations.

## Quick start (local, demo mode)

Double-click `index.html`. Every page uses relative paths and the font is embedded, so the site works opened straight from disk, or from any static server:

```bash
cd checkaeo
python3 -m http.server 8080      # optional; open http://localhost:8080/
```

With `SCAN_API_URL` unset the site runs in **demo mode**: the checker explains the scanner isn't connected and offers "See an example AEO Card" (three bundled examples, clearly labelled as examples). Everything else — the card, export, copy, share, the full report — works exactly as it does live.

## Going live

See **DEPLOY.md**. Short version:

1. Deploy the scanner as **either** a Cloudflare Worker (`cd worker && npx wrangler deploy`) **or** an AWS Lambda Function URL (`cd worker && ./build-lambda.sh`, upload the zip). Same engine, your choice of cloud.
2. Put its URL in `assets/js/config.js` → `SCAN_API_URL`.
3. Optionally add your GA4 ID in the same file.
4. Upload the site folder to any static host (Cloudflare Pages, Netlify, Vercel, GitHub Pages, S3…).

## How scoring works

Overall = Access × 0.30 + Clarity × 0.25 + Answers × 0.25 + Trust × 0.20. Every check, its points and its pass condition are published at `/methodology/` and implemented in `worker/src/analyze.js`. Gating rules stop a non-200 or noindexed page from being masked by good content scores. Optional/emerging signals (llms.txt, alt text, lang) are reported but weigh nothing. In the Answers category, FAQs, question headings and definition sentences are supporting signals only (15 points combined) so a plain, clear homepage can score well without them.

**Grounding rule (hard):** "What AI sees" is always a verbatim sentence from the page, labelled with its source (meta description / main heading / opening text) and prefixed "Appears to be about:" unless confidence is high. Fix suggestions are built only from facts found on the page; anything not found is rendered as a `[bracketed placeholder]`, never invented.

## The card export

The on-page card is HTML/CSS. The export is a **separate SVG render** of the same data (`card.js → buildCardSVG`) with the Manrope font embedded as a data URI, rasterised to PNG at 2× on the client. Three sizes: square 1080×1080, portrait 1080×1350, landscape 1600×900. No screenshot library, no server.

## Calibrating the score on real sites

```bash
cd worker && node test/calibrate.mjs stripe.com anthropic.com quotabird.com "https://en.wikipedia.org/wiki/Plumber"
```
Prints one line per site (score, grade, status, four category scores, what AI sees, top fix). The question to ask of each line: *does the score feel directionally right before reading the explanation?* If a clearly excellent site scores badly on Answers for lacking FAQ-style structure, or a thin page scores well by ticking boxes, adjust the weights in `worker/src/analyze.js` and the table on `/methodology/` together.

## Tests

```bash
cd worker && npm test
```

Covers scoring of good/vague/blocked pages, robots.txt parsing (longest-match, wildcard), noindex handling, unreachable pages, and URL/SSRF validation.

## Accessibility & performance

WCAG 2.2 AA target: semantic landmarks, one H1 per page, visible focus rings, `aria-live` scan status, screen-reader text for the score and every check status (never colour-only), keyboard-operable menus, `prefers-reduced-motion` respected. Total JS ≈ 40 KB uncompressed (half of it demo data), one 28 KB font, no third-party scripts unless GA4 is configured.
